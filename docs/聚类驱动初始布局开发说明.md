# 聚类驱动初始布局开发说明 · 第一版

2026 年 11 月 5 日 · 今晚的编码计划。随机布局已有正式入口和验收记录，本页的聚类规则、接口和命令均为本次拟实现内容。第一次看项目，可以先读第 1、2 节，再照第 4 节开始写。

## 1. 我们要做什么

把芯片想成一块画板，电路单元是大小不同的小矩形。一条**网**记录哪些单元上的接线点要连在一起。随机布局会各自给小矩形找位置。聚类布局先把经常连在一起的矩形分成小组，再把同组成员放在附近。代码里把这样的小组叫作**簇**。

程序读入原电路，最后导出一份新的 `.pl` 位置表和一份 JSON 检查报告。每个可移动单元的**整个矩形**都要在区域内，固定单元保留原位置，包括本来就在区域外的固定端子。初始布局允许重叠，后续步骤会再调整位置。

已有流程可以直接接着用。读入整理层已经把文件里的左下角坐标换成程序内的中心坐标。新方法只负责计算可移动单元的新中心，现有保存函数会把中心换回左下角。

```text
读入原始电路 → 记录固定位置 → 选用布局方法 → 检查结果 → 保存位置表和报告
                                ├─ random  已有随机布局
                                └─ cluster 今晚新增：算连接分数 → 合组 → 按小格落位
```

## 2. 第一版怎么算

课件给出了按连接强弱合组、更新小组位置、在组内按格摆放的流程。下面的分数、上限和小格尺寸是本项目第一版的取值，先写在代码里，方便复现和验收。

### 2.1 给连接打分

1. 按 `Nodes`、`Terminals` 的原有顺序给单元编临时编号，以 `isFixed` 判断能否移动。每个可移动单元先单独成组。固定单元参与网的统计，但只给两个可移动单元之间记分。
2. 从 `db.Nets` 的每条网找到管脚，再通过 `pin->module` 找到所属单元。同一个单元在同一条网上可能接了多个管脚，算分时只数一次。设去重后整条网有 `k` 个不同单元，包含固定单元。
3. 当 `2 ≤ k ≤ 16`，这条网给其中每一对可移动单元加 `1 / (k - 1)` 分。两条网连了同一对，分数相加。网里连的人越多，每对分到的分数越少。少于两个可移动单元的网直接跳过。

代码里可以用整数记分，把 1 分看成 360360 份。它能被 1 到 15 整除，所以每次用 `360360 / (k - 1)` 加分，并用 `std::int64_t` 保存累计值。同分就能直接比较，避免小数误差改变合并顺序。

真实电路中有单条网连上千个管脚的情况。第一版跳过含 17 个及以上不同单元的网来控制配对数量。这条限制只用于分组。原有线长统计继续使用所有网和所有管脚，连到固定单元的线也照常算。

### 2.2 每次合并符合上限且分数最高的两组

- 一组最多 **8 个可移动单元**。合并后的面积上限取 **最大可移动单元面积**和 **8 倍平均可移动单元面积**中较大的一个。面积按宽乘高计算，小组面积等于成员面积之和。先处理没有可移动单元的情况，直接结束。
- 每次选分数最高、合并后同时满足人数和面积上限的两组。分数相同时，先比每对里较小的组编号，再比另一个编号，均优先选小的。为新组发一个递增编号。合并后，把原来两组到同一邻组的分数加起来。例如 A 到 C 有 2 分、B 到 C 有 1 分，合并后的 AB 到 C 就是 3 分。
- 找不到还能合并的正分组合就停止。没有连接、连接很少或面积较大的单元可以保持单独一组，也要获得坐标。

实现时只记录有分数的组对。用 C++ 的 `priority_queue` 随时取出最高分，避免每次都扫遍所有组。原来两组被合并后就标为失效，从相邻组的记录里清掉旧连接，并把新连接放入队列。队列里如果还留着旧组的记录，取出来时直接跳过。按稳定编号处理同分项，别让哈希表的遍历顺序决定合并顺序。

### 2.3 给每组安排位置，再把成员放进小格

1. 复用随机布局的区域检查、中心可选范围和随机数生成方式，按 `--seed` 为每个可移动单元生成一个**临时中心**，先存在临时数组里。部分样例原文件里很多可移动单元都从原点出发，所以单独生成一套临时中心。种子影响摆放位置，分组只由接线和大小决定。
2. 合并时按面积平均两组的中心。横坐标是 `(A 面积 × A 的 x + B 面积 × B 的 x) ÷ 两组面积之和`，纵坐标同理。面积大的组对新中心影响更大。
3. 只有一个成员的组直接沿用它的临时中心。其他组以组中心为基准画一个小框，基础边长取 **√(2 × 组面积)**。框的宽、高分别至少容纳组里最宽、最高的单元，并各自限制在整个区域的宽、高以内。必要时平移小框，让它落在区域内。
4. 组里有 `m` 个成员时，列数取 `√m` 向上取整，行数取 `m ÷ 列数` 向上取整。从小框的左下开始，先从左到右，再换到上一行，按成员原编号依次把中心放到小格中央。小格用于分配中心位置，较大的单元可能跨格。
5. 每个单元最后还要按自己的宽高把中心限制到安全范围内。例如区域横坐标是 `0～100`，一个宽 20 的单元，中心横坐标只能在 `10～90`。直接复用现有 `centerRange` 的安全端点，避免小数转成程序使用的 `float` 后越界。所有目标中心算完并检查通过，再一次写回 `Module::center`。

## 3. 先在纸上走一遍

假设 A、B、C、D 是四个可移动单元，都宽 2、高 2。F 是固定单元。画板从 `(0,0)` 到 `(100,80)`。为方便手算，这一例将每组人数上限临时设成 2。

| 一条网里的单元 | 这条网给组对增加的分数 |
| --- | --- |
| A、A、B | A 重复接线，去重后 A–B 加 1 |
| A、B、F | 全网有 3 个不同单元，A–B 再加 0.5 |
| B、C、F | B–C 加 0.5 |
| C、D | C–D 加 1 |

先合并 A、B，得分 1.5。合并后 AB 到 C 还有 0.5 分。再合并 C、D，得分 1。此时 AB 到 CD 有 0.5 分，但四个成员超过示例上限，分组结束。

如果 A、B 的临时中心分别是 `(10,10)`、`(18,10)`，两者同样大，组中心就是 `(14,10)`。AB 总面积为 8，小框边长为 4，切成两列一行。两个格子的中心为 `(13,10)` 和 `(15,10)`，分别是 A、B 的新中心。F 的坐标全程保持原样。

## 5. 今晚怎样验收

- **先看算法。** 用第 3 节的例子核对分数、合并顺序和新坐标，再用实际人数上限 8 检查一次。补上同分、面积超限、含 17 个不同单元的网、孤立单元和全固定等小例子。测试中要能看出分组影响了坐标，单看位置表是否有效还无法确认走到了聚类算法。
- **再走完整流程。** 先跑只有 4 个单元的 `thin1`，确认位置表正常、报告中有 `"method": "cluster"`，再依次跑 `adaptec1`、`adaptec4`。每个电路用同一程序和种子各跑两次，分别保存，核对输出坐标、单元名单、固定标记和边界。大电路另记布局耗时，若资源受限，记录实际停在哪一步。
- **最后对比随机。** 从同一套原始文件分别运行两种方法，保存到不同位置，记录 HPWL 和布局耗时。HPWL 可以理解为给每条网的管脚画一个外框，把外框的宽和高相加，再加总到所有网。通常越小越好，今晚先看数据和差异，验收以算法正确、结果有效为准。

下面是接通聚类后在 WSL 中可用的 `thin1` 验收命令。Windows 构建沿用 [已有开发说明第 12 节](初始布局开发说明.md#12-已完成版本怎样运行)。

```bash
set -e
cd '/mnt/d/综合设计III参考资料/任务4参考/MyPlacement_DataDefine'
cmake -S . -B build/cluster-linux -DCMAKE_BUILD_TYPE=Release
cmake --build build/cluster-linux --parallel 4

data='../../任务2参考/BookShelf格式的解析/thin1'
mkdir -p test_data/cluster_results
for run in first repeat; do
  ./build/cluster-linux/myplace --input-dir "$data" --benchmark thin1 \
    --method cluster --seed 42 --output "test_data/cluster_results/thin1_${run}.pl"
done
python3 test_data/check_random_output.py --input-dir "$data" --benchmark thin1 \
  --output test_data/cluster_results/thin1_first.pl \
  --repeat-output test_data/cluster_results/thin1_repeat.pl
```

`check_random_output.py` 会重读位置表和接线数据，并在终端输出独立算出的 `hpwl`。把它和 `thin1_first.pl.report.json` 里的 `hpwl` 对照，沿用随机验收脚本的小数比较容差。同时核对程序报告里的 `method`。旧的 `run_random_acceptance.py` 中有一条「`--method cluster` 应报错」的检查，接通新方法后将它移出失败用例，改用一个未知方法检查错误提示。测试脚本和生成结果放在本机的 `test_data/`，遵循团队约定。

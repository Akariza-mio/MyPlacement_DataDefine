# 二次方程解析布局开发说明

2026 年 11 月 6 日 · 第一版 · 任务 4

这份说明用一个小例子解释程序怎么给芯片上的单元找位置，再列出代码入口和验收值。第 1、2 节可以直接读，第 3 节的记账表可和代码对照。正式程序通过 `--method quadratic` 运行，验收结果记在[初始布局开发进度](初始布局开发进度.md)。

## 1. 布局是在找什么位置

把芯片想成一块画板，把**单元**想成画板上的小矩形。每个单元上有几个接线点，叫**管脚**。一条**网**就是一份接线清单，列出哪些管脚要连在一起。有些单元的位置已经固定，其他单元由程序安排。

可以把要连接的管脚想成被小弹簧牵着。拉开一点，代价小一些。拉开两倍，平方代价就变成四倍。程序把所有弹簧的代价加起来，寻找总和最低的位置。每一轮先把弹簧的强弱定下来，再算出让它们平衡的位置。这样，**要最小化的是带平方的代价，实际求的是一组一次方程**。

比如只看横向，两个固定管脚在 `0` 和 `12`，一个可以移动的管脚在 `x`。如果两条弹簧一样强，代价就是 `x² + (x − 12)²`。放在 `x = 2`，代价是 `4 + 100 = 104`。放在中间 `x = 6`，代价是 `36 + 36 = 72`。若右边的弹簧更强，平衡点会向右移。真实电路里，一个单元会同时被许多连接拉着，所以要把方程放在一起解。横向和纵向可以分开算。

今晚得到的是后续优化的起点。每个**可移动单元的整个矩形**都要在布局区内。固定单元即使原本就在区外，也保持原位并参与计算。初始位置可以重叠，后续任务再处理疏密和摆放行。

## 2. 一轮布局是怎么跑的

```text
所有可移动单元先从布局区中心起步
                ↓
用当前管脚坐标算横向、纵向的连接权重
                ↓
分别解出横向和纵向的新中心
                ↓
按每个单元的宽高把中心限制在安全范围内
                ↓
用这一轮限制后的坐标开始下一轮
```

**先找管脚，再算连接强度。** 管脚的绝对位置等于“所属单元的中心 + 管脚相对中心的偏移”。例如单元中心为 `(10, 8)`，管脚偏移为 `(+2, −1)`，管脚就位于 `(12, 7)`。一条网有 `P` 个管脚时，按课件给每一对管脚计算权重，每对只算一次。横、纵各用自己的距离。首版沿用课程运行参考的距离下限 **25 个输入坐标单位**和 **3 轮**设置。

```text
当前轴上的距离 d = abs(管脚 p 的绝对坐标 − 管脚 q 的绝对坐标)
当前轴上的权重 w = 1 / ((P − 1) × max(d, 25))
这一对在该轴的代价 = w × (求解时的两个管脚坐标之差)²
```

距离下限让两个管脚即使已经对齐，仍能算出有限的权重。同一单元上的两个管脚会一起移动，彼此距离恒定，跳过这一对。两个固定管脚的距离也恒定。它们仍计入该网原始管脚数 `P`。同一单元的两个不同管脚若分别和别的单元连接，两份贡献都要记下来。空网和单管脚网直接跳过。

**再解方程，最后限位。** 这一轮的权重取自轮首坐标，在各自的求解过程中保持不变。两轴求解都通过后再限位。比如区域横向是 `0～100`，宽 20 的单元中心只能在 `10～90`。解得 `x = 95` 时，把它落在 `90`。下一轮使用限位后的坐标重新计算权重。限位保证结果能落进区域，线性方程的误差应在限位前检查。[课程《初始布局设计》第 2–11 页](../../初始布局设计.pdf#page=2) · [课程运行数据参考](../../二次方程解析初始化布局-运行数据参考.docx)

## 3. 把连接关系写进方程

### 3.1 一对管脚怎么记账

对任一方向写成 `A · u = r`。`u` 是所有可移动单元在这一轴的中心，`A` 是各个方程的系数表，`r` 是等号右边的数。横向和纵向的权重分别计算，因此两套系数可以不同。下面按一对管脚来累加，每轮每轴都从零开始。

| 当前这对管脚 | 给 `A` 加什么 | 给 `r` 加什么 |
| --- | --- | --- |
| `i`、`j` 都可移动 | `A[i,i]`、`A[j,j]` 各加 `w`，`A[i,j]`、`A[j,i]` 各减 `w` | `r[i] += w × (offset_j − offset_i)`，`r[j] += w × (offset_i − offset_j)` |
| 一个可移动 `i`，一个固定 `f` | `A[i,i] += w` | `r[i] += w × (固定中心_f + offset_f − offset_i)` |
| 两个都固定，或都属于同一个单元 | 跳过这一对 | 跳过这一对 |

例如固定管脚在 `(12, 7)`，可移动单元的管脚偏移为 `(−1, +2)`，且这两个管脚之间是唯一一条连接。求解后的可移动**中心**应为 `(13, 5)`，这时两个管脚正好对齐。把输入中的两个管脚交换顺序，应得到同样的结果。上表的 `r` 已经是求解器直接接收的右端项。课件将目标展开为 `uᵀAu + bᵀu + c` 时使用的是线性项系数 `b`，对应这里的 `r = −b/2`。

### 3.2 一整组都没有固定参照怎么办

如果几个单元互相连着，却连不到任何固定单元，整组一起平移时管脚间的距离都不变，方程就没法选出唯一的绝对位置。首版的做法是按网找出能互相连通的组。遍历每条网，把其中的可移动单元合入一组，并记录有没有连接到固定单元。连通关系可以先算一次，后面三轮复用。

每个无固定参照的组按稳定编号选一个代表 `i`。在 `A[i,i]` 加一项 `λ`，在 `r[i]` 加 `λ × 代表的初始中心坐标`。`λ` 取该行原有对角值，孤立单元用 `1`。这样相当于让整组有一个参考位置。限位前，整组可以平移到这个参考位置而保留原来最优的相对摆法。已有固定参照的组直接用原方程。孤立单元保持初始中心。这里的参照只存在于求解数据里，`isFixed` 始终表示输入中的真实固定状态。

### 3.3 求解和大电路内存

首版沿用课件用 Eigen 处理稀疏方程的思路。这里的**稀疏**是指系数表中许多位置都是零，程序可以只存需要用到的系数。补齐固定参照后，每轴的系数表都满足共轭梯度法的条件。实现用 `Eigen::ConjugateGradient` 和它默认的对角预处理，从上一轮坐标开始逐步求解。系数、右端项和求解使用 `double`，落位时再转成现有 `float` 坐标。[Eigen 稀疏方程求解文档](https://eigen.tuxfamily.org/dox/group__TopicSparseSystems.html)

成功报告中的 `quadratic_solves` 按轮次和方向记录每次建表、求解和误差检查的结果。把算出的 `u` 代回方程，用 `‖A · u − r‖ / max(1, ‖r‖)` 检查等号两边差多少，首版的阈值为 `1e-8`，每轴最多 1000 次迭代。这里的次数是**解一套方程的内部步数**，外层按课程样例做 3 轮。误差超限、遇到无效数字或求解失败时，程序结束本次布局并报告电路名、轮次、方向和误差。

| 本地电路 | 可移动单元 | 最大单网管脚数 | 全部无序管脚对 | 实际需参与建表的管脚对 |
| --- | ---: | ---: | ---: | ---: |
| `thin1` | 3 | 3 | 4 | 4 |
| `adaptec1` | 210,904 | 2,271 | 7,519,729 | 6,623,239 |
| `adaptec4` | 494,716 | 3,974 | 22,984,433 | 20,786,109 |

数据来自本地 `.nodes`、`.pl` 和 `.nets`。建表列已扣除同单元对和双固定对。同一矩阵位置仍可能收到多个管脚对的贡献。`adaptec4` 每轴若存一整张 `494,716 × 494,716` 的 `double` 表，约需 1.96 TB。先按轴分别建表和求解，只存对角线与下三角的系数。对角线单独累计，两个端点都可移动的管脚对只提交一条下三角记录，同位置的多条记录压缩时相加。求解和复核误差时都按完整的对称矩阵计算。第一轴的候选坐标先放在临时数组中，释放该轴的矩阵和建表空间后再处理第二轴。两轴都从同一轮的起点取数。

大电路的建表工作随每网管脚对数增长。先记录每轴压缩前后的项数、建表和求解耗时、进程峰值内存，再判断是否需要改进存储。首版按课件遍历所有有效对。若大电路遇到资源限制，把具体规模和停在哪一步写进进度，后续单独评估模型取舍。

## 4. 代码如何接入工程

| 顺序 | 改动与落点 | 写完先核对 |
| --- | --- | --- |
| Q01 准备坐标和编号 | [myplace.h](../MyPlace/myplace.h) 声明 `MyPlacer::quadraticPlace`，可选择接收每轴的求解记录。[myplace.cpp](../MyPlace/myplace.cpp) 复用 `collectPlacementRanges`。按现有范围列表给可移动单元连续编号，以 `Module*` 查行号。 | `Module::idx` 是读入器的编号。以 `isFixed` 判断可移动性。全固定时直接返回，固定单元的范围和坐标无需调整。 |
| Q02 建表和求解 | 从 `PlaceData::Nets → Net::netPins → Pin::module` 取连接，按 `Pin::offset` 算绝对位置。[CMakeLists.txt](../CMakeLists.txt) 通过 `Eigen3::Eigen` 接入求解器。 | 小例子的横纵轴符号、同网多管脚、重复贡献累加、无参照组和孤立单元结果可手算。 |
| Q03 迭代和落位 | 在临时数组中逐轮更新坐标。检查两轴结果有限、方程误差达标，再按每个单元的安全中心区间限制坐标。全部候选检查通过后统一写回 `Module::center`。 | 中途失败时原坐标保留。固定位置保持原样，靠边单元转成 `float` 后整个矩形仍在区内。 |
| Q04 接入正式入口 | [myplace_main.cpp](../myplace_main.cpp) 接收 `--method quadratic`，复用读入整理、固定位置快照、`inspectPlacement`、`writePl` 和 JSON 报告。 | 报告能识别 `quadratic`。省略方法仍默认 `random`，`--groups` 仍只用于 `cluster`。解析布局从区域中心起步，`--seed` 对它的坐标无影响。 |
| Q05 跑验收 | 先手算，再跑 `thin1`，随后跑 `adaptec1`、`adaptec4`。三种方法都独立读取同一份原始数据。 | 保存命令、实测结果和未完成项到[初始布局开发进度](初始布局开发进度.md)。 |

读入整理层已经把 `.pl` 左下角换成中心。管脚偏移来自 `.nets`，布局区来自 `.scl`。布局只更新中心，导出时现有 `writePl` 再把中心换回左下角。遍历时先验证指针及归属，再读偏移和坐标，测试直接构造内存数据时也要覆盖坏引用。临时测试与输出放在工程的 `test_data/`，沿用团队约定。

## 5. 怎么判断写对了

**先验小例子。** 跑第 3.1 节的非零偏移例子，再跑两个可移动单元串在固定端之间的例子。若固定端在横坐标 `0` 和 `12`，三条连接等权且偏移为零，每个可移动单元都在自己的两个邻居正中间。两个中心 `a`、`b` 满足 `2a − b = 0` 和 `−a + 2b = 12`，解得 `a = 4`、`b = 8`。这个例子用来验一轮的建表与求解，可以直接给定权重。随后检查距离为零、多脚同属一个单元、只有固定单元、没有参照的组，以及失败时的位置保护。

为核对三轮都重新计算了权重，让一个单元从 `(0,0)` 起步，两条两脚网分别连到 `(0,0)` 和 `(100,20)` 两个固定点，管脚偏移均为零。在中心为原点、三次落位都无需限位的区域内，三轮横坐标应依次约为 `20`、`23.80952`、`24.70588`，纵坐标始终为 `10`。

**用 `thin1` 核对完整流程。** 固定单元 `o211025` 的 `.pl` 左下角为 `(6240, 22)`。读入后中心为 `(6276, 238)`，其管脚位于 `(6299, 443)`。两条网的管脚在未限位时可以分别对齐。按实际管脚偏移计算，三个可移动单元的预期中心如下。

| 单元 | 限位前的理想中心 | 限位后的中心 |
| --- | --- | --- |
| `o100852` | `(6290.5, 443)` | `(6290.5, 465)` |
| `o100851` | `(6301, 438)` | `(6301, 465)` |
| `o50015` | `(6284, 445)` | `(6284, 465)` |

这三个单元的高度都是 12，布局区底边为 `459`，所以中心最低只能到 `465`。比较时按单元名匹配，中心和 HPWL 可先用 `0.01` 个坐标单位的绝对误差核对课程参考值。固定左下角、方向和 `/FIXED` 标记逐项检查。预期 HPWL 约为 **29**。HPWL 是给每条网的管脚画一个外框，把框的宽和高相加，再把各网相加得到的线长估计。它用来比较结果，建表时用的是第 2 节的平方代价。[课程 `thin1` 运行记录](../../二次方程解析初始化布局-运行数据参考.docx)

**最后跑大电路和三种方法的对照。** 正式构建需要 Eigen 3.4 或兼容版本的 CMake 包。本轮在 Windows 和 WSL 共用安装到 `build/deps/eigen-install` 的 Eigen 3.4.0。换电脑可使用系统已有的 Eigen，或将 `CMAKE_PREFIX_PATH` 指到自己的安装目录。Windows 沿用已有 Ninja 构建命令，构建目录换成 `build/quadratic-windows-ninja`，配置时加 `"-DCMAKE_PREFIX_PATH=$(Join-Path $PWD 'build/deps/eigen-install')"`。 [Eigen 3.4.0 官方源码包](https://gitlab.com/libeigen/eigen/-/archive/3.4.0/eigen-3.4.0.tar.gz) · [Eigen 的 CMake 配置说明](https://libeigen.gitlab.io/eigen/docs-3.4/TopicCMakeGuide.html)

在 WSL 的项目根目录运行下列命令。为每个电路、方法和重跑分别保存输出。

```bash
set -e
cmake -S . -B build/quadratic-linux -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_PREFIX_PATH="$PWD/build/deps/eigen-install"
cmake --build build/quadratic-linux --parallel 4

data='../../任务2参考/BookShelf格式的解析/thin1'
mkdir -p test_data/quadratic_results
./build/quadratic-linux/myplace --input-dir "$data" --benchmark thin1 \
  --method quadratic --output test_data/quadratic_results/thin1.pl
python3 test_data/check_random_output.py --input-dir "$data" --benchmark thin1 \
  --output test_data/quadratic_results/thin1.pl
```

现有独立检查脚本可重读输出，核对单元无遗漏、无重复、可移动矩形零越界、固定位置和标记保持原样，并独立计算 HPWL。检查报告里的 `method`，同一环境用相同输入复跑一次，再记录三种方法的 HPWL、布局耗时和峰值内存。先以方程、小电路和输出有效性判断实现是否正确，再解释 HPWL 的实际差异。课程要求至少设计并比较三种初始化方法。[任务描述第 2 页](../../../工业软件创新训练III-任务描述2026.pdf#page=2) · [已有 Windows 构建命令](初始布局开发说明.md#12-已完成版本怎样运行)

# 一些开发时的注意事项

## 无论你使用AI还是手写，请务必注意下面这些事

1.在你新创建的每个.h文件（头文件）的第一行，一定写上#pragma once：

```
#pragma once
..你的代码
```

这句话保证这个头文件只会被编译一次，大大提高效率，在原来的模板代码中也有“保证编译一次”的检查，形如：

```C++
#ifndef <头文件名>
#define <头文件名>
...
#endif
```

但是这样的方法效率很低，且会有可能发生重定义问题。

2.h文件和cpp文件的一致性

h文件一般是声明类，结构体，以及一些通用声明，在**同名**cpp文件中定义（这里的同名不是必然要求，只是看上去更好阅读和维护）。这样做的目的是避免重定义风险，加快编译速率和可读性。

- 声明：只写出某个函数的签名

```C++
//在某个.h文件的类中
class test{
    void readBookShelf(const string& dir,const string& benchmarkname);
}
```

- 定义：实现这个函数

```C++
#include "头文件名.h" //如果你要实现某个类的成员函数，请在cpp文件中第一行引用这个类所在的头文件
//在同名的.cpp文件里
void test::readBookShelf(const string& dir,const string& benchmarkname){
	//具体实现
}
```

3.非常建议不要在.h文件中使用

```C++
using namespace std;
```

具体原因可以网上搜索，但是由于原来的代码模板已经用了，这里就随意了，出问题了再说吧，但是如果要进行C++开发，这个习惯是非常错误的。

4.关于测试

大家可以随意进行测试，只是测试文件建议统一放在test_data，然后==测试脚本和临时生成结果不要pull request提交到仓库里==

5.关于cmake

由于我们会使用cmake构建这个项目，因此如果你在测试时新建了build这个文件夹，请把它删掉，或者直接使用.gitignore强制忽略它（使用方法可自行搜索），==不要上传到仓库==
